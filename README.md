# 智算网络规划与仿真平台 Demo

## 本地启动

需要 Node.js 20.19+ 或 22.12+。

~~~powershell
npm ci
npm run dev -- --host 127.0.0.1
~~~

打开终端显示的本地地址。运行 npm run build 可生成静态产物 dist，运行 npm run preview 可预览产物。

## 演示路线

1. 从项目中心打开哈尔滨移动项目，点击「运行仿真」计算示例基线。查看链路热力图、时序曲线、热点流量来源和 A2 / A5 约束。
2. 在资源和负载模块修改配置。回到仿真工作台选择正常或 SP01 下线场景后运行。历史任务保存每次运行的输入快照。
3. 在寻优页填写允许的整数档位，逗号分隔。单值固定该变量。运行后检查筛选原因、可行性和 Pareto 方案。Pareto 比较成本、吞吐和 P99。
4. 保存候选后可复跑其输入快照，或在「方案与报告」下载 JSON、设备及链路 CSV、Markdown 评估报告。

项目数据保存在当前浏览器。示例输入集中在 src/demo.json。设备规模、负载、价格和约束是演示数据。

## 导入数据

- 资源页可下载当前配置的 Excel 样表或 JSON。JSON 接受配置对象或包含 config 的对象。Excel 第一张表为 key,value，字段名使用样表中的键。
- 可选 Excel 表 Links 包含 leaf,spine,ports，代表两个域的完整上联关系。JSON 使用 connections 数组。可选 Excel 表 Attachments 或 JSON attachments 包含 endpoint,nodes，调整各接入组的节点数。节点总数须与项目资源池一致。
- 通信矩阵接受 CSV 或 TSV，依次填写 时间ms,源端点,目的端点,消息MB,并发,类型。端点名来自连接清单，例如 D02-C01 或 D02-S01。也可用计算端点之间的矩阵描述 PD 或 MoE 通信。

## 计算口径

- 标准拓扑为两个独立网络域的两级 Clos。每个接入端点聚合一个 Leaf 下的同类节点。ECMP 使用有限个确定性路径分片。
- 仿真以 0.5 ms 推进。每步逐次分配端到端路径中的链路带宽、存储读写吞吐和 IOPS。峰值利用率取时间步内单向最大值。延迟包含等待、传输和配置的设备基础服务时间。未完成或无路由消息单独检查完成率。
- 存储模型使用项目录入的容量、持续读写吞吐、IOPS 和基础延迟。两个网络域的资源分开记账。现场验收需用实测设备及负载参数校准。
- 寻优保留第一个域的上联与接入，按变量重建第二个域的接入和上联。先校验容量、端口和连通性，再跑仿真。可靠性选项可要求候选同时通过两个域 SP01 下线的场景。

## 通用拓扑展示

- 画布按网络域展示 Spine、Leaf 和端点资源池，从当前拓扑对象汇总设备、物理上联和接入节点。设备清单和连接关系保留可用于导入的稳定编号。
- 「资源与网络建模 → 展示设置」可修改项目的网络域名称和沿用设备标签。哈尔滨示例在项目数据中配置 A2、A5 和「利旧」。容量规划项目可用「现网域／扩容域」，通用模板使用编号命名。
- 当前引擎支持两个独立网络域的两级 Clos，计算和连接引用使用 D01、D02。旧项目、旧拓扑文件和旧通信矩阵中的 A2、A5 结构编号会自动转为通用编号。项目业务名称仍按原配置展示。

- 拓扑 JSON 可包含 display，例如 {"domains":{"D01":"训练域","D02":"推理域"},"assigned":"沿用"}，与 config 同级。Excel 使用可选 Display 表，列为 key 和 value，键为 D01、D02 或 assigned。缺省展示字段沿用目标项目的现有设置。
