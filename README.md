# 智算网络规划与仿真平台 Demo

## 本地启动

需要 Node.js 20.19+ 或 22.12+。

~~~powershell
npm ci
npm run dev -- --host 127.0.0.1
~~~

打开终端显示的本地地址。运行 npm run build 可生成静态产物 dist，运行 npm run preview 可预览产物。

## 演示路线

1. 从项目中心打开哈尔滨移动项目，进入「评估工作台」点击「运行评估」。查看链路热力图、时序曲线、热点流量来源和 A2 / A5 约束。
2. 在资源和负载模块修改配置。部署模型可选预置名称或自定义，性能仍按固定部署的参数计算。回到评估工作台，按需展开「故障校核」，选择交换机或链路。历史任务保存每次评估的输入及故障对象。
3. 在资源页拓扑中点选分组、设备或链路，在右侧「对象属性」开启允许调整的维度并填写候选值，再运行评估。系统评估正常组网和每个选中的故障，逐项比较指标。Pareto 比较成本、吞吐和 P99。
4. 保存候选后可复跑其输入快照，或在「方案与报告」下载 JSON、设备及链路 CSV、Markdown 评估报告。

项目数据保存在当前浏览器。示例输入集中在 src/demo.json。设备规模、负载、价格和约束是演示数据。

## 导入数据

- 资源页可下载当前配置的 Excel 样表或 JSON。JSON 接受配置对象或包含 config 的对象。Excel 第一张表为 key,value，字段名使用样表中的键。
- 可选 Excel 表 Links 包含 leaf,spine,ports，代表两个域的完整上联关系。JSON 使用 connections 数组。可选 Excel 表 Attachments 或 JSON attachments 包含 endpoint,nodes，调整各接入组的节点数。节点总数须与项目资源池一致。
- 通信矩阵接受 CSV 或 TSV，依次填写 时间ms,源端点,目的端点,消息MB,并发,类型。端点名来自连接清单，例如 D02-C01 或 D02-S01。也可用计算端点之间的矩阵描述 PD 或 MoE 通信。

## 计算口径

- Clos 生成器为每个集群生成两级 Clos 设备与连线。集群数量独立可选。现网导入可表达其他物理连接结构。选路使用有限个确定性路径分片。
- 仿真以 0.5 ms 推进。每步逐次分配端到端路径中的链路带宽、存储读写吞吐和 IOPS。峰值利用率取时间步内单向最大值。延迟包含等待、传输和配置的设备基础服务时间。未完成或无路由消息单独检查完成率。
- 存储模型使用项目录入的容量、持续读写吞吐、IOPS 和基础延迟。两个网络域的资源分开记账。现场验收需用实测设备及负载参数校准。
- 寻优按开放的设备组、链路或批量规则生成候选。先校验容量与端口，再用实际连接运行仿真。故障校核逐个下线所选对象。候选中已停用或缺失的故障对象标为不适用，候选不计为达标。

## 通用拓扑展示

- 画布按物理网络分区，纵向展示 Spine、Leaf、计算和存储节点。分组级按角色与型号汇总，设备级可查看实例和连接；多条并行链路可以从关联链路中逐条查看。
- 集群名称和设备分组名称在对象拓扑内配置。哈尔滨示例使用 A2、A5 和「利旧」作为项目数据。
- 当前引擎支持两个独立网络域的两级 Clos，计算和连接引用使用 D01、D02。旧项目、旧拓扑文件和旧通信矩阵中的 A2、A5 结构编号会自动转为通用编号。项目业务名称仍按原配置展示。

- 拓扑 JSON 可包含 display，例如 {"domains":{"D01":"训练域","D02":"推理域"},"assigned":"沿用"}，与 config 同级。Excel 使用可选 Display 表，列为 key 和 value，键为 D01、D02 或 assigned。缺省展示字段沿用目标项目的现有设置。

## 固定部署下的推理评估与网络寻优

哈尔滨示例默认使用同一「业务负载建模 → 评估工作台」流程。项目配置包含 A2、A5 的模型、请求速率、固定实例和并发槽位。其他项目使用相同的数据结构、页面和计算入口。

- 按固定速率投放请求。每个请求使用相同的模型配置和逻辑分片键。请求依赖的读取和后台持久化复用流级网络引擎，竞争设备服务能力与链路。只有依赖读取完成后，请求才进入固定实例的算力队列。
- 算力用单槽 Prefill 速度及固定生成间隔近似。TTFT 包含依赖读取、算力排队和首 token 计算。TPOT 由给定生成间隔决定。示例数据可替换为实际部署和测试参数。
- 资源页可在分组规则或实际对象旁配置候选值。关闭某维度会锁定当前值。候选复用同一批请求和算力部署。哈尔滨只开放 A5 侧的调整项，A2 侧保持原配置。
- 通信画像和通信矩阵继续通过同一个引擎做独立的流级诊断。推理评估使用以秒为单位的请求施压时长，网络内部按 1 ms 推进。

### 评估工作台

在资源与网络建模的对象属性中设置候选范围，导入或手动编辑的当前值作为基线独立保存。进入评估工作台后，使用「运行评估」。基线全部锁定时执行单方案评估，开放维度时筛选并比较候选；已保存的同输入、同场景基线指标可复用，链路明细按需生成。评估结果与方案报告位于同一工作台，查看候选诊断后可单独决定是否保存。

## 对象拓扑

新建项目可选择「从 Clos 生成」「导入现网」或「空白建模」。生成时单独选择集群数量、Spine、Leaf 和端口速率，随后和文件导入一样进入统一的对象拓扑资源页。可在「分组级」选中分组并展开查看实际设备，也可直接切换「设备级」。异构设备可通过对象拓扑导入，或在资源页编辑型号和实例。

哈尔滨的旧参数在加载时展开为同一套对象，保留 A2/A5 归属、基线容量与成本、业务负载及候选范围。原有方案和历史快照保留旧口径，可继续打开。新评估按逐设备、逐端口选路，时延可能与旧聚合模型不同。旧版完整 Clos JSON 和 Excel 可导入并转换。

JSON 可直接提供 version 为 1 的对象模型，也可用 model、workload、limits、search 组成项目输入包。Excel 每张表与一个对象集合对应。

| JSON 字段 | Excel 工作表 | 主要字段 |
| --- | --- | --- |
| clusters | Clusters | id、name |
| networks | Networks | id、name，可选 maxHops |
| models | Models | id、name、kind（switch / compute / storage）、portCount、maxGbps。可选 ratesGbps、cost、switchGbps。计算型号可填 slots。存储型号填写 capacityPB、readGBps、writeGBps、iops、latencyMs |
| devices | Devices | id、model、cluster、role、state、enabled、group。计算节点须有唯一集群归属，可通过计算池指定。交换机可供多个集群使用 |
| ports | Ports | id、device、maxGbps（可选，用于限制该端口） |
| links | Links | id、a、b（端口编号）、gbps、network、enabled、state、cost、upgradeCostPerGbps。批量规则可引用 group 和 order |
| pools | Pools | id、kind、members（设备编号）、clusters（可访问集群编号）。Excel 列表以逗号分隔 |
| groups | Groups | id、name，供设备分组和批量规则引用 |
| batchRules | BatchRules | id、name、kind、current。device-count 使用 group，uplinks-per-leaf 使用 group 和 leafGroups，attachment-distribution 使用 sourceGroups、targetGroups 和 linkGroup |
| faultDevices | Faults | 选填。JSON 为交换机编号列表，Excel 为 id 列 |

- 对象编号在项目内按类型唯一。多条链路可以使用同一对设备的不同端口；每个端口同时只能占用一条启用链路。按同一物理网络内的最少跳数选路，实际端口和链路分担带宽。型号配置的交换容量作为每台交换机独立的共享上限。
- 存储池允许多个集群引用。容量指标表示各集群可访问的容量，共享容量在物理层保留一份。链路、交换机与存储 I/O 都按实际对象共享预算。通信矩阵第七列可选填归属集群。
- 在资源页选中链路后，可在右侧开放速率或启用状态，交换机及存储设备也可开放启用状态。扩容时可先建好标记为 added 且停用的对象，再将启用加入候选。候选只保存对象变更，基线拓扑独立保留。
- 点选设备分组后，右侧可配置已建模的批量规则，包括启用库存中的设备、按档位调整每台 Leaf 的已建模上联，以及按规则重分配存储接入。候选运行前展开成设备启用、链路启用和端口接线变更，复核时从同一快照重建。导入拓扑可以用同一对象结构定义批量规则。
